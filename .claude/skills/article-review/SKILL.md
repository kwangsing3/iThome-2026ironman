# iThome 鐵人賽文章校稿基準

給 kwangsing3 的 2026 鐵人賽系列使用。系列主張:**「AI 負責人類到不了的地方,而不是取代人」**。校稿時每一項建議都要同時服務這個主張與下列指標。

搭配專案根目錄的 `CLAUDE.md`(30 天排程、三系統三部曲、發文策略)一起讀。三部曲第一篇已正名為「人類的極限篇」(不再叫痛點篇),敘事一律用疆界/規模框架 — 見 §3。

---

## ★ 校稿總基調:帶思考,不推銷(凌駕全表,先讀這條)

**這一條是所有維度的上位定位,每一項建議都要先過它。** 這系列的目的是**協助讀者自己想通**,不是說服讀者接受作者的結論。凡是校稿建議會讓文章更像「推銷」而非「帶思考」,即使它服務了 GEO/SEO/展示力,也要往回收。

- **重點是帶領思考,不是推銷觀點**:作者提出主張,是為了給讀者一個能驗證、也能反對的靶子,不是要讀者照單全收。看到「把結論塞給讀者」的語氣,改寫成「把材料攤開、邀請讀者自己判斷」。
- **實例是證明手段,不是改寫想法的工具**:三系統、截圖、數字只用來證明「這件事真的做得到」,不是用來證明「所以你該同意我」。實例負責 show 事實,結論留給讀者自己下。
- **避免直銷感(硬檢查)**:禁止「你一定要」「這就是答案」「相信我」「照著做就對了」「你會發現你需要…」這類話術;連「AI 一定會 / 一定不會取代 X」這種替讀者拍板的斷言也算。改寫成開放句:「你可以自己驗證看看」「這是我的做法,你的場景未必一樣」。
- **留白優於填滿**:能讓讀者自己得出的結論就不要替他講完;作者把路鋪到面前,最後一步讓他自己走。
- **與其他節的關係**:本條與 §3「不下指導棋」、§7「反 hype」同源但範圍更廣——§3 管「人被推向哪」的留白,§7 管未來感不吹捧,本條管**整篇的說服姿態**。三者衝突時,以本條(不推銷、帶思考)為最高原則。
- 檢查法:讀完全篇問一句「這篇是在**幫我想清楚**,還是在**要我點頭**?」偏向後者 → 標為必改,指出是哪些句子造成推銷感,給開放句改法。

### 🚫 禁套語:不用「一句話」「留給你自己想」這類概括公式(硬規則,對文章與校稿輸出都適用)

**這是 kwangsing3 明確點名的嚴重問題。** 下列「概括敘事套語」一律禁止——它們是典型 AI 生成腔,讀者一眼聞得出來,會直接摧毀「真人實作」的可信度(反噬 §1 E-E-A-T 護城河,也是本系列最大護城河):

- ❌ **摘要收尾套語**:「一句話(總結/重述)」「總之」「說到底」「歸根究柢」「簡而言之」——先鋪一個模板殼、再把結論塞進去的寫法。
- ❌ **敷衍式留白套語**:「(答案)留給你自己想」「這就交給你了」「你自己去體會」——用一句空話假裝把選擇權給讀者。

**⚠️ 本條同時管校稿輸出本身**:給 kwangsing3 的建議句、改寫示範裡也不准出現上述套語。校稿者自己用「一句話」,等於在示範 AI 腔給作者看,雙重失格——寫建議前先自檢。

**允許 / 禁止的界線(別矯枉過正)**:

- ✅ **結論先行(GEO 導向)照舊鼓勵**:段落 / H2 第一句直接給出**有實質內容的結論**,是 §1 GEO 核心手法,不受本條限制。差別在——給的是**結論本身**,不是「一句話,+ 結論」這種包裝殼。
  - ❌「一句話:CVE 是規模 × 時效的雙重牆。」 → ✅「CVE 是規模 × 時效的雙重牆。」(拔掉殼,結論照樣先行,還更有力)
- ✅ **真正的留白(§3 認知鐵則)照舊要做**,但必須是**具體、扣住當篇內容的開放問句**(如「空出來的餘裕,你會拿去做什麼?」),不是「留給你自己想」這種通用敷衍句。留白要讓讀者有東西可想,不是把思考責任丟回去了事。

檢查法:看到「一句話」「總之」「留給你自己想」這類模板詞,先問「拔掉這個殼,句子會不會更有力?」——幾乎總是會,拔掉。

**分工**:本 skill 管**專案專屬的審稿重點**(正向敘事、真實性、保密、一致性、未來感)。文章「怎麼寫」的通用craft(骨架、TL;DR-first、H2 問句化、段落紀律、自檢清單)在 **geo-seo-writing** skill。**校稿一篇時兩個一起套**;GEO/SEO 結構細節以 geo-seo-writing 為準,下面 §1/§2 是專案角度的補充。

## 使用方式

當使用者要求校稿或給建議時:

1. 先判斷這篇屬於哪個性質(①名詞 / ②思考 / ③定位 / ④設計 / ⑤實作 / ⑥收尾)與哪個系統,不同性質權重不同(見各節)。
2. **先套「★ 校稿總基調」**(帶思考不推銷)當上位濾鏡,再過 §0 兩道硬門檻(主幹問題 + 實際案例回答);沒過就是必改,優先報。接著依 §1–§7 各維度逐項檢查,**只回報有問題或可提升的項目**,不要把全部清單覆誦一遍。任何 §1–§7 的建議若會增加推銷感,以總基調為準往回收。
3. **§8 心理學閱讀分析(單篇必做,不可略)**:§1–§7 檢查完,一定要另開一段,用兩道鏡回推——① 閱讀順序(讀者從上到下,情緒/注意力怎麼跑)② 單詞造成的印象(哪個字/標點按到哪個心理鈕)。這是這份 skill 對「單篇」校稿的固定產出,不是選配。
4. 每個發現給:**問題 → 為什麼(扣哪個指標)→ 具體改法(直接給改寫句子,不要只說「建議加強」)**。
5. 最後給一個「這篇最該先改的 3 件事」的優先序。
6. 不確定的事實、數據、來源 → 標記為待查,不要替使用者杜撰。

## §0 兩道硬門檻(每篇必過,先檢這個)

這兩項是「有沒有」的門檻,不是程度問題。**沒過 → 直接列必改,優先於其他所有維度。**

- **① 主幹問題**:這篇有沒有**一個**明確的主幹問題——整篇就在回答的那一個核心問題?
  - 一篇只扛一個主幹問題;標題與前導 TL;DR 必須對得上它,所有 H2 都服務它。
  - 檢查法:讀完能不能用一句話說出「這篇在回答的問題是 ___」。說不出 / 有多個並列主題 → 失焦,必改。
- **② 用實際案例回答**:這個主幹問題是不是用**真實案例 / 實際例子**回答的,而不是空泛論述?
  - show, don't tell:要有具體情境、真實數字/畫面/流程,不是「一般來說會…」「通常建議…」。
  - 沒有實際案例 → 必改,或標「待補真實例子」問作者。帶案例時一併套 §5 去識別化、§4 可驗證。
  - 這是本系列「真實上線」護城河的最小要求(呼應 §4 真實性、§5 保密、§7 展示力)。

## §1 GEO — 讓生成式 AI 願意採納(最高權重)

目標:當有人問 ChatGPT / Claude / Perplexity / AI Overviews 相關問題時,這篇會被引用、被當成答案來源。

檢查項:

- **結論先行**:每個段落、每個 H2 底下第一句就是答案或重點,不要鋪陳三段才講重點。AI 摘錄時抓的是前幾句。
- **可獨立抽取**:每一段拿掉上下文也讀得懂。避免「如上所述」「前面提到的那個」這種指涉;把主詞補回去。
- **問句式 H2**:標頭寫成使用者真的會問的問題(「AI Agent 跟 chatbot 差在哪?」),對齊 AI 的 query 比對。
- **明確定義專有名詞**:第一次出現 CCW / CVE / RAG / Embedding / Agent 時,一句話定義 + 中英對照(以 GLOSSARY §二 為準)。AI 靠這個建立實體關聯。**本系列不主打 Fine-tuning**,選路軸線用 RAG vs Prompt。
- **結構化呈現**:能用表格就用表格(比較、成本、適用場景),能用有序清單就用有序清單(步驟),能用 Q&A 就用 Q&A。結構化內容被 AI 抽取的機率遠高於長段落。
- **具體數字與時間**:「省下多少時間」「擋掉幾個風險」「幾秒完成」要有數字;日期寫絕對日期不寫「上個月」。可引用性 = 可信度。
- **可引用金句**:每篇至少有 1–2 句自成完整、可被單獨引用的總結句(定義句、對比句、結論句)。
- **E-E-A-T 訊號**:強調「真實上線」「實際被業務/維運使用」「我親手做的 pipeline」— 第一手經驗是 AI 判斷權威性的關鍵,也是本系列最大的護城河。
- **術語一致**:同一概念全系列用同一個詞(例:固定用「向原廠互動的下單系統」不要一下「報價系統」一下「詢價工具」;以 GLOSSARY 為準)。不一致會稀釋實體訊號。

## §2 SEO — 瀏覽器搜尋

- **標題含關鍵字**:英文關鍵字(CCW、CVE、RAG、Agent、GraphQL…)放進標題與 H2,對齊實際搜尋字串。
- **🚫 標題禁詞「實戰」(硬規則)**:單篇文章標題**一律不得出現「實戰」**——此詞已被濫用、帶負面觀感。**唯一例外**:系列總標題可保留(《…系統整合商 AI 導入實戰(2026)》)。校稿見到任何單篇標題含「實戰」即標為**必改**,改用更具體的動詞(實作 / 示範 / 拆解 / 上線 / 走查等)。內文可斟酌,但標題零容忍。
- **標題「相關即可」,不必與排程/索引完全相等**:iThome 是論壇發文,真正的貼文標題填在平台的**獨立標題欄位**;文章裡的 MD `# H1` 只是**導讀**用。校稿時,H1 與 CLAUDE 逐日排程 / D01 索引的標題**只要主題相關、不誤導讀者**即可,**不要**把「字句不完全一致」列為必改的不一致(內文概念詞的術語一致仍適用,見 §1 術語一致 / §6)。
- **前 200 字給結論**:開頭直接講這篇能解決什麼、結論是什麼,兼顧跳出率與精選摘要。
- **H2/H3 層級清楚**:一篇一個核心 H1(標題),H2 分段落,H3 分細節;不要跳級。
- **系列內鏈(不列入校稿)**:30 篇互鏈能養整個系列的權重——但**現階段是 MD 草稿,連結由作者在發佈成網路文章時於平台手動補**(平台形式與 MD 不同)。因此**校稿不得把「MD 裡沒有 markdown 內部連結」列為缺失或建議項**;文內有「提到相關篇章(Dx)」讓作者知道日後要鏈到哪,就足夠了。
- **圖片 alt**:架構圖、截圖要有描述性 alt text(含關鍵字)。
- **適當長度與段落**:段落 3–5 行內,長句拆短;避免整屏無斷點。
- **關鍵字自然分布**:核心詞出現在標題、首段、至少一個 H2、結尾;不要硬塞(關鍵字堆砌反傷排名)。

## §3 正向敘事 — 不要負面呈現(重要,且需與 CLAUDE.md 調和)

**規則**:描述「人類做不到的客觀極限」是正向的(這正是本系列的主場);抱怨工具爛、廠商雷、同事扯、我採了什麼坑,是負面的,要改寫或拿掉。

> **與三部曲第一篇「人類的極限篇」的關係**:每個系統第一篇是「人類的極限篇」(原稱痛點篇,已正名)。**它的功能是建立「人類不可及」,敘事框架必須是「疆界/規模」而非「抱怨/採坑」**:
> - ✅ 框成**疆界/規模/機會**:「人工組一張報價單要比對上百種型號相容性 — 這是規模問題,不是誰不夠努力。」
> - ❌ 不要框成**抱怨/挫折/採坑**:「這流程有夠爛」「CCW 的文件超難用害我卡三天」。
> 客觀難度留著(它撐起主張),情緒與歸咎拿掉。

檢查項:

- **把痛點改寫成「人類疆界」**:凡是講困難,結尾要導向「所以這是 AI 該接手的規模/速度/不間斷疆域」,而不是停在抱怨。
- **不點名貶低**:不批評特定廠商、產品、同事、前人。要講限制就講客觀限制(「人一天只能讀這麼多 CVE」),不講「誰做得爛」。
- **採坑改成設計取捨**:與其寫「我踩了 X 坑」,寫成「我在 A 與 B 之間選了 A,因為…」— 同樣有資訊量,但呈現的是判斷力(對齊「人負責判斷」主張)。
- **失敗經驗正向化**:真的要講走過的彎路,框成「這讓我學到判斷 X 的準則」,收在方法論而非情緒。
- **對「人」永遠正向**:講自動化時,一律保留「人被釋放去做更高價值的判斷」,不要讓讀者(尤其同事)覺得被威脅(呼應 D10)。
- **不下指導棋(協助認知 > 改寫想法,全系列鐵則;「★ 校稿總基調」在雙承諾上的落地)**:雙承諾的「人被推向哪」要**留白**,不要替讀者指定「該去做 X」的具體終點。目的是**協助讀者自己認知**那塊被釋放的餘裕,不是替他決定——具體指定終點會變成下指導棋,引發心理牴觸(尤其抗拒的同事)。檢查法:凡看到「人(該/會/要)去做+具體動作」的斷言句,改寫成**開放問句/邀請**(「空出來的餘裕,你會拿去做什麼?」)。寫法上:**AI 半句可具體**(規模/速度是事實),**人半句留白**。前一項「人被釋放去做更高價值判斷」是精神,不是要你把終點寫死。與 CLAUDE.md「認知鐵則」及開頭「★ 校稿總基調」對齊。

## §4 真實性與可驗證性(競賽硬分 + GEO 可信度)

- **數據要能追**:效益數字(省時、擋掉風險數)標明來源或估算方式;不確定就寫範圍或標「內部估算」,不要編。
- **程式碼可信**:文內程式碼片段要能對應真實 repo/gist;關鍵邏輯正確,不要為了好看貼假 code。
- **外部事實附來源**:CVE 編號、Cisco 版本、標準定義 → 給官方連結。
- **不替使用者杜撰**:校稿時若發現需要具體數字/事實而稿子沒有,標為「待補」,問使用者,不自行填。

## §5 保密與合規(真實公司系統,務必把關)

這三系統是某系統整合商內部真實上線系統,寫作時:

- **🚫 絕對紅線(不可違反)**:①**公司一律不具名**,寫「某系統整合商」;②**三系統上線日期一律不揭露**(連「去年」「上季」這類相對時間也避免);③效益數據只用**去識別化案例**。校稿發現任何一項就標為必改。
- **不外洩敏感資料**:真實客戶名、內部 SKU/報價明細、內網結構、實際設備清單與 IP、帳密、內部價格與折扣邏輯 → 一律遮蔽或改為示意值。
- **CVE/設備篇特別小心**:不要揭露自家設備的未修補漏洞現況或版本弱點細節到可被利用的程度。講方法與架構,不公開自家攻擊面。
- **可示範但去識別化**:程式碼、schema、範例資料改成 demo 版;GraphQL introspection 之類的示範用公開或去識別化的例子。
- **有疑慮就標記**:發現可能觸及機密的段落,主動提醒使用者確認可否公開。

## §6 系列一致性與可讀性

- **敘事弧線對位**:確認這篇在「認知→思考→設計→實現→收尾」的位置,語氣與深度符合該階段(認知段面向廣泛讀者、實作段可深)。
- **扣主標**:每篇至少一處明確呼應「AI 負責人類到不了的地方 / 而不是取代人」的雙承諾。
- **三部曲節奏**:實作系統的三篇(人類的極限 → 實作 → 後續引用)結構一致;第三篇務必有「真的被誰用、產生什麼效益、人被釋放去做什麼」。
- **非工程師讀得下去**:痛點/疆界篇與收尾篇避免術語轟炸;必要術語即時解釋。
- **結構模板**:情境/疆界(30%)→ 做法/實作(50%)→ 可複製結論或程式碼(20%)。
- **收尾有 CTA/鉤子**:結尾點下一篇要講什麼,維持連載黏性。

## §7 Show-don't-tell、未來想像力與展示力(Grounded Futurism)

**Show, don't tell 是全系列鐵則,適用每一篇(含鎖定篇、含實作篇)。** 本節額外處理一批「鋪陳篇」的任務:**帶同事想像未來 + 幫他們認知作者設計的系統**。

檢查項(全篇適用):

- **展示 > 宣稱**:能給 demo、截圖、架構圖、數據、實際畫面就別用形容詞堆疊。「幾秒跑完人工一天的量(附畫面)」勝過「非常強大、劃時代」。
- **開場錨點**:每篇前 3 句給一個具體、會讓人「哇」的畫面/數字/情境,把讀者拉進現場。
- **動態語感**:標題與開頭用「正在發生、規模、速度」的現在進行式措辭,而非靜態教科書口吻。
- **前瞻鉤子**:結尾埋「下一步 / 未來會怎樣」,維持連載的前瞻感與黏性(可與 §6 的 CTA 合併)。

「鋪陳篇」額外檢查項(帶同事入場的非實作篇):

- **雙讀者意識**:除了 iThome 大眾/評審,設想**公司同事**也在看。目的是讓內部團隊**先看見未來、先認得作者設計的系統**,降低抗拒(呼應 D8/D10)。
- **幫助認知系統**:清楚點出系統「是什麼、解決什麼、長什麼樣」,讓同事讀完能說出「喔這就是他做的那套」。系統名稱以 GLOSSARY 為準,一致稱呼。
- **系統鋪陳(有意無意帶到)**:非實作篇**可穿插真實系統的畫面/成果當例子**,替 D18+ 實作篇養熟悉感——但**點到為止,不喧賓奪主、不變成實作教學**(完整走查留給實作篇)。

- **🚧 反 hype 護欄(硬規則,優先於本節)**:每個未來感宣稱都要有可運作證據(呼應 D2「去敘事、去 hype」與 §4 可驗證)。**禁用空詞**:顛覆、革命性、劃時代、賦能、無所不能。本節**不得凌駕** §3 正向敘事、§4 真實性、§5 保密;衝突時以那三節為準。未來感來自「真的做到了」,不是喊「這是未來」。帶到系統畫面/成果時,一併套用 §5 去識別化。

## §8 心理學閱讀分析(單篇必做,兩道鏡)

**這是單篇校稿的必要呈現,不是選配。** 校稿一篇時,除了 §0–§7 的清單式檢查,一定要另開一段「從讀者腦內的實際體驗回推用詞」的分析。§總基調、§3 留白、§7 反 hype 處理的最深層機制都是**讀者心理**——本節把它顯性化,固定用下面兩道鏡。發現要具體到「哪一句 / 哪一個詞 → 在讀者腦裡造成什麼印象 → 換成什麼、為什麼」,不能只說「開場可以更好」。

### 🧠 鏡一:閱讀順序(讀者從上到下,情緒與注意力怎麼跑)

- **逐拍拆開場**:把前導/開場拆成幾「拍」(第一句 → 第二句 → 首個 H2…),標出每一拍在讀者腦裡是**升高喚起**(恐慌/威脅/興奮)還是**降低喚起**(冷靜/信任/安心)。畫出這條情緒曲線。
- **第一印象最黏**:第一句 / 前 3 行決定整篇定調,後面很難翻。檢查第一拍有沒有把讀者帶到你要的情緒——本系列要的是**冷靜、去 hype、讀者在主控**,不是相反。
- **降溫別來太晚**:若開場先點燃 hype/恐慌,拖到第三、四拍才「其實我很冷靜」——順序錯了。把降溫、可信度、grounding 往前挪,讓第一印象就是你要的框。
- **粉紅大象**:凡「先把威脅畫清楚、再否定」的寫法(「你要被 AI 取代了!……但其實不會」),等於先幫對手把恐懼植入。檢查有沒有無意間替反方敘事放大音量。
- **框架讓渡**:開場第一句若引用外部大聲敘事(媒體/CEO/華爾街),等於第一秒把麥克風交給對方、讓對方定義戰場。本系列要自己定調,不讓渡(呼應 D2 去 hype)。

### 🔤 鏡二:單詞造成的印象(逐詞的連想與體感)

- **一個動詞/名詞就換一種體感**:同義不同感——「負責一塊地」(抽象、靜態)vs「扛一個戰場」(負重、身體感)vs「打一場仗」(對抗、神化);「守不住」(謙卑、人仍在場)vs「做不到」(可能刺自尊)。挑詞前想清楚要按到哪個心理鈕。
- **標點也是詞**:驚嘆號 = 提高音量/喚起;問號 = 邀請思考;破折號 = 停頓強調。去 hype 的篇,開場慎用驚嘆號。
- **擬人與位階**:「讓 AI 去…」把 AI 放在**下位**(讀者主控、焦慮低);把 AI 寫成英雄/主體(征服、顛覆)會**神化 AI、搶走人的主角位**。
- **否定句先喚起被否定的詞**:「不是取代人」會先讓「取代人」浮現;斟酌那個詞要不要第一個出現。
- **對兩種讀者的分歧反應**:同一個詞,焦慮的同事和老鳥工程師可能相反解讀(如「戰場/打仗」→ 老鳥覺得帥、同事覺得威脅)。挑詞要能**同時服務雙讀者**,或至少不傷任一方(呼應 §7 雙讀者、§3 對人正向)。
