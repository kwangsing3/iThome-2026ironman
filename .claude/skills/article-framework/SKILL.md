# 單篇文章框架產生器(寫作 Tips 讀取點)

## 使用方式

當使用者要「生某一篇的框架/大綱」時,依序:

1. **先讀三處**:本 skill 的「寫作 Tips 清單」、`CLAUDE.md`(該篇的性質/階段/🔭/💻 標記與主線定位)、以及 GLOSSARY(用語、系統資訊)。
2. **套 geo-seo-writing 的六區塊骨架**(標題→前導 TL;DR→問句 H2→視覺錨點→數據來源→收束+下一篇鉤子)。
3. **套 article-review §0 硬門檻**:框架必須先寫出這篇的**主幹問題(一句話)**與**要用哪個實際案例回答**。
4. **逐條檢查下方 Tips**,有適用的就落實並在框架裡註明「(依 Tip N)」。
5. 產出框架後,列出「本框架套了哪幾條 Tip」讓使用者一眼看到。

## 框架輸出格式(建議)

```
# Day X 框架:《標題》
- 主幹問題(§0):___
- 用來回答的實際案例(§0):___
- 讀者定位:新手/資深/實作(依 Tip 1 分級)
- 前導 TL;DR(3–5 行):鉤子 + 結論
- H2 大綱(每個都是問句、節首給答案):
  1. ...
  2. ...
- 視覺錨點:圖/表/code/示範(哪一段放什麼)
- 數據/來源:___
- 承先啟後(依 Tip 3):承前(前約 2 篇)___ ｜ 啟後(後約 2 篇)___
- 收束 + 下一篇鉤子:___
- 本框架套用的 Tips:#1 ...
```

## 寫作 Tips 清單(持續累加)

### Tip 1 — D1 必須放「讀者分級導引」

在 **D1(開場索引)** 除了列出全 30 篇標題與比重,**務必標出哪幾篇適合新手、哪幾篇給資深、哪幾篇是實作/火力展示**,讓不同程度的讀者知道怎麼挑讀,降低中段流失。

以現有規劃的分級基準(可隨排程調整):

| 分級 | 適合對象 | 天數 |
| --- | --- | --- |
| 🟢 新手友善 | 外行、轉職者、非企業視角也讀得懂 | D1、D2、D3、D5、D6、D7、D30 |
| 🟡 需一點背景 | 有基本產業/職場概念 | D4、D8、D9、D29 |
| 🟠 資深/管理視角 | 有組織經驗、需推動與決策 | D10、D11、D12、D13、D14、D28 |
| 🔵 實作/火力展示 | 有開發背景,看真實系統 | D15–D27 |

備註:
- D6、D13 除分級外另標 💻(一定有 code/示範),D1 導引可順帶點出「想先看動手內容?從 D6 開始」。
- 產 D1 框架時,把這張表轉成讀者導引段落(可做成表格或「三條閱讀路線」:新手線 / 決策者線 / 工程師線)。

### Tip 2 — 實作篇要明確指出「讀者可以帶走什麼」

每一篇實作篇(D15–17 基礎應用、D19/D22/D25 系統實作)**都要有一個明確的「帶走重點 / Key Takeaways」區塊**,直接告訴讀者這篇看完能拿走什麼,不要讓讀者自己歸納。

- **放在收束段**(接 geo-seo-writing §6),用清單條列 3–5 點,每點一句、可獨立成立(利於人跳讀 + AI 抽取)。
- **帶走的是「可遷移的東西」,不是「照抄的 code」**——因為系統是火力展示、非照抄教學(見 CLAUDE.md §六)。所以重點寫成:**模式 / 原則 / 判斷點 / 踩過的取捨 / 適用與不適用的情境**,而非「複製這段就能跑」。
  - D15–17(基礎應用):可較具體,給可重複套用的手法與最小範例的要點。
  - D19/D22/D25(系統實作):給**做法背後的通用模式**(例:如何用 introspection 免手刻 schema、如何設計版本比對、如何規模化擷取),讓讀者帶走思路而非公司內實作。
- **每點盡量對回這篇的主幹問題(§0)**,讓「帶走重點」就是主幹問題的答案濃縮。
- 可搭配一句「這招在什麼情況適用 / 什麼情況不要用」,提高可信度與實用度。

### Tip 3 — 每篇要有「承先啟後」提示,扣住前後約 2 章

每一篇框架都要放一個 **承先啟後區塊**,明確點出這篇跟**前約 2 篇**、**後約 2 篇**的關聯,提醒作者寫的時候把連續性做出來——讓 30 篇讀起來是一條線,不是 30 個孤島。

- **承前**:一句話交代「前 1–2 篇立了什麼、本篇接著往下講什麼」,開頭可用一句回扣(呼應 geo-seo §3 自足段落,但補一句銜接即可,不要長篇複述)。
- **啟後**:一句話埋「本篇的結論會通往後 1–2 篇的什麼」,收在結尾鉤子(與 geo-seo §6「下一篇鉤子」合流,但視野放到 +2 篇,不只 +1)。
- **用系列內鏈落實**(呼應 article-review §2 系列內鏈):承前/啟後提到的天數,寫作時做成內部連結,養整季 SEO 權重。
- **對三部曲要順著節奏扣**:實作三部曲(人類極限→實作→後續引用)天然有前後關係,承先啟後要順著三部曲寫,不要跳。跨系統時(如 D20→D21)點出「換到下一個系統、但共通模式一樣」。
- 產出時在框架的「承先啟後」欄填好承前/啟後各一句,並標出對應天數;若前/後不足 2 篇(如 D1、D2、D29、D30),就寫實際可扣的篇數。
