# 鐵人賽技術文章寫作規範(GEO + SEO + 人類可讀性)

核心前提:**GEO 與人類可讀性同源**——兩者都要「答案給得快、資訊切得乾淨」。為「趕時間、只想掃一眼看懂」的讀者寫,AI 檢索自然也吃這套。

## 與 article-review 的分工(兩者一起用)

- **本 skill(geo-seo-writing)= 文章「怎麼寫」的通用 craft**:骨架、前導 TL;DR、H2 問句化、段落紀律、視覺錨點、GEO 機制、自檢。
- **article-review = 本專案「該檢查什麼」**:§0 主幹問題+實際案例硬門檻、正向敘事、真實性、保密硬約束、系列一致性、Grounded Futurism。
- **校稿一篇時兩個都套**:先用本規範顧結構與可讀性/GEO,再用 article-review 顧專案紅線與調性。GEO/SEO 結構細節以**本規範為準**。

## 何時套用

- 技術部落格文章、教學、實作紀錄、系列連載(如 iThome 鐵人賽)。
- 任何目標是「被 Google 搜到 + 被 AI 搜尋(ChatGPT / Perplexity / Gemini / Google AI Overviews)引用」的長文。

---

## 一、文章骨架(六個必備區塊)

每個區塊都必須同時服務「機器檢索」與「人類閱讀」。

### 1. 標題

- 問句化,或明確描述可搜尋的問題(「什麼是 X」「怎麼做 X」「X vs Y 該選哪個」)。
- 埋入英文技術關鍵字(如 RAG、Embedding、Agent、CVE、GraphQL)——AI 的查詢分裂(query fan-out)會用這些詞搜尋。
- 主標可有情緒鉤子,關鍵字塞副標,兩者兼顧。
- 反例:「X 概述」「淺談 X」「關於 X 的一些想法」(對機器與人都弱)。

### 2. 前導(前 3–5 行,對應搜尋摘要區)

兩拍節奏:

1. **鉤子**:一個場景、痛點或反常識陳述,抓住人類注意力。
2. **TL;DR**:立刻講明「這篇會證明什麼、結論是什麼」。

- 前 200 字必須直接回答主問題,不鋪陳。即時檢索的 AI 主要看開頭判斷相關性。
- 禁止暖場句(「在開始之前,我們先聊聊……」「眾所周知……」)——對機器與人都是負擔。

### 3. 分節本文(H2 分段)

- 每個 H2 寫成一個問句或明確子問題。
- **自足段落原則**:每節開頭先給該節的答案 / 結論,再往下解釋。讓 AI 能單獨抽走一節當引用,讓人類跳讀不漏重點。
- 一個 H2 只處理一個問題,不混題。

### 4. 視覺錨點(打斷文字疲勞)

- 每隔數段插入一個非文字元素:架構圖、對比表格、程式碼片段、流程圖。
- 給眼睛喘息點,同時提供 AI 可擷取的結構化資訊。

### 5. 數據與來源

- 放具體數字、百分比、實測數據(引用來源能明顯提升 AI 引用率,對人是信任訊號)。
- 引用權威來源(官方文件、研究、規範)並標註。

### 6. 收束 + 下一篇鉤子

- 用一句話重述本篇結論(對 AI 是強化,對人是安心落地)。
- 留一個懸念指向下一篇,形成序列化鉤子(留住連載讀者 + 內部連結利於 SEO)。
- 範例:「這套系統能秒出結果,而它接下來怎麼進到團隊的日常維運——那是明天的事。」

## 二、段落紀律(控制資訊壓力)

- **一段一個念頭,上限 3–4 句**。超過就拆段。
- **會變成逗號長串的內容,一律改成清單**。「要考慮 A、B、C、D、E」→ 拆成逐條、每條一句。
- **每節開頭一句 signposting**,說明「這節要處理什麼」,讓讀者知道自己在文章旅程的哪個位置。
- **技術重段之後,接一句白話連接句**喘息,避免硬內容連續砸下。
- 善用留白;不要出現整螢幕沒有斷點的文字牆。

## 三、GEO / AI 搜尋要點(機制對應做法)

| AI 搜尋機制                                        | 對應寫法                                     |
| -------------------------------------------------- | -------------------------------------------- |
| 查詢分裂(query fan-out):把問題拆成多個子查詢分頭搜 | 標題與標頭埋入使用者實際會搜的英文技術關鍵字 |
| 標頭與查詢做語意配對                               | H2 寫成問句,鏡像真實搜尋語句                 |
| 依開頭段落判斷相關性                               | 前 200 字直接給結論(TL;DR-first)             |
| 偏好含數據、來源、專家引言的內容                   | 放具體數字與可查證來源                       |
| 偏好標註日期的新鮮內容                             | 標題或內文帶年份(如 2026)                    |

避免:關鍵字硬塞(機器與 Google 都會懲罰)、把內容切成無意義碎片、依賴 llms.txt 等「撇步」(對 Google AI 搜尋無效)。**扎實的 SEO 本身就是 GEO。**

## 四、發文前一眼自檢清單

- [ ] 開頭 5 行是否已給出結論 / TL;DR?
- [ ] 標題是否問句化並含英文關鍵字?
- [ ] 每個 H2 是否為問句、且節首先給答案?
- [ ] 最長段落是否超過 4 句?(超過就拆)
- [ ] 逗號長串是否已改成清單?
- [ ] 是否至少有一個圖 / 表 / 程式碼作為視覺錨點?
- [ ] 是否有具體數字或引用來源?
- [ ] 結尾是否重述結論並勾住下一篇?
- [ ] 是否存在整螢幕無斷點的文字牆?(有就拆)
